# P13 Recovery Implementation Plan

> **For agentic workers:** Use executing-plans and test-driven-development.

**Goal:** Gateway-owned private full snapshot and isolated restore proof.

**Architecture:** Add an opt-in configured recovery layer and three narrow MCP
tools. Stream immutable evidence; use SQLite backup; verify restored data inside
an isolated Gateway. Keep private manifests/receipts outside Git.

**Tech Stack:** Python stdlib, SQLite backup, existing Gateway/MCP and pytest.

## Global constraints

- All production and restored V2 access occurs inside formal Gateway tools.
- No arbitrary path arguments, deletion, overwrite or guessed provenance.
- V1 retirement waits for all required prior Gates; WorkBuddy remains pending.
- Existing read-only configs and non-History domains remain compatible.

## Tasks

1. Configuration and protection: append optional AppConfig fields, validate
   recovery TOML, reject Git/target overlap and invalid keys. Write RED tests.
2. Snapshot: add focused recovery filesystem/database helpers and orchestrator;
   synthetic WAL, immutable reuse and corruption tests; verify GREEN.
3. Isolated restore: compare bytes/schema/counts/row digests; compose isolated
   Gateway; canonical/source/ledger proofs and overwrite guards. RED → GREEN.
4. MCP: opt-in admin-only discovery and strict argument handling, no private
   paths in results/errors. In-memory MCP tests are engineering evidence only.
5. Independent review, targeted/full checks, package/privacy audit and docs.
6. Configure private root and run the actual configured native Host; durable
   receipts and sanitized checkpoint. No Agent-side DB fallback.
