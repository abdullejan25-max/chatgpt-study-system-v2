# Unified Provenance and P1-P9 Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add trustworthy, shared provenance to persistent writes and resolve cross-phase contract gaps found in the P1-P9 architecture audit.

**Architecture:** Each private SQLite database gets the same append-only provenance ledger; domain tables remain specialized. Gateway/storage code generates UTC timestamps, source/origin classifications, versions, and supersession links; identity/session strings are optional caller-reported data and explicitly unverified. History imports add import-specific fields without exposing a new MCP write capability.

**Tech Stack:** Python 3.11+, SQLite, pytest, MCP Python SDK, existing `uv` project environment.

## Global Constraints

- The Agent host is the only intelligence layer; Gateway operations remain deterministic.
- Do not add an LLM/VLM or generative model/provider API dependency.
- Do not modify or test against real StudyVault, History, wrong-answer, textbook, archive, or image data.
- Keep source evidence immutable and distinguish source, deterministic derived, Agent-generated, imported, and system-generated data.
- Do not begin Phase 10, real-data migration, real JPG E2E, push, publish, or add a remote.
- MCP-reported identities are unverified; all write timestamps are generated by Gateway/runtime UTC clocks.

- `ensure_provenance_schema(connection) -> None` creates or migrates the ledger idempotently and tags safely identifiable pre-existing records as `pre_provenance`.
