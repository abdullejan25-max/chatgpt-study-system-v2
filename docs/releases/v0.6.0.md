# v0.6.0 — Cross-Agent Integration

Codex、WorkBuddy、Hermes 的三个独立 Agent/Host 已通过同一 Gateway data layer
完成真实跨 Agent handoff，继续保持 Agent thinks; Gateway executes。
本次复用正式 workflow 和 Projection，未新增业务层或第二份权威 Memory。

- 真实 Hermes 0.20.0 创建合成 Document/source/v1；WorkBuddy 5.7.3 新会话按
  marker 自主发现并追加 v2；Codex CLI 0.159.2 新会话独立读取完整版本链。
- 自然语言任务不含对象 IDs、MCP method、DB path 或前轮 DTO；只需 GUI
  trust/任务发送/退出，无人工数据中继，无 session/Memory 补数。
- Source/v1/provenance、时间戳、logical refs 保持原样；v2 明确 supersedes v1。
  所有 Agent identity 仍为 caller-reported / unverified，不能当作安全认证。
- 完整相同 request/key 重放返回相同 v2；实际 stale expected-version 新请求
  由 Gateway 返回 CONFLICT，最终 total=2/versions=[1,2]，无 v3。
- A/B 退出后 fresh Codex exact 读取 Asset/document/page/source/v1/v2；不存在
  marker 正式查询为0，不从本地文件或旧会话补答案。
- 最终 scoped Gateway collector → renderer → manifest writer 生成14 Markdown，
  两次 Markdown/manifest byte-identical，无原始 Asset bytes/私人路径/重复记录。
  Projection 保留既有分类 provenance 摘要，完整自报 Agent identity 在 Host DTO
  回执中比较，不宣称投影 UI 展示完整身份。
- 强化已有三独立 stdio 进程回归：文档 MCP ingest、schema/workflow parity、
  完整 DTO 比较、版本唯一性、exact replay、conflict/no-result。
- Codex 已知 resources/list 兼容问题仍 deferred/nonblocking；最小 Host 指引
  直接读取固定 canonical URI。Hermes 工具描述的 nullable/oneOf 展示差异留档，
  正式 Gateway 参数与互斥校验保持不变。

验收与失败记录见 [Step 4 checkpoint](../p12-step4-cross-agent-checkpoint.md)。
原始 Host configs/traces/session exports、所有 isolated stores/Vault 留在 Git 外。
